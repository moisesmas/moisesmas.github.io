Tus datos: progreso y copia

Todo se guarda solo en este navegador. Puedes descargar tu progreso para llevarlo a Aules; la sesión de terminal se descarga desde la pestaña «Terminal». Este simulador no usa Git real ni se conecta a ningún servidor.

Terminal simulada

Escribe órdenes de Git sobre un repositorio que vive solo en la memoria de esta página. Empieza con git init -b main. Usa las flechas arriba y abajo para recuperar órdenes anteriores y help para ver lo que entiende el simulador.

Qué entiende el simulador (y qué no)
  • Git: init, config, status, add, commit (con -m, -a), log (--oneline, --graph, --all), diff (--staged), branch, switch, checkout, merge (--no-ff, --abort), restore (--staged) y rm.
  • Archivos: ls, cat, echo "texto" > archivo (también >> y -e para saltos de línea con \n), touch, rm y nano archivo (abre un editor de texto sencillo).
  • No existe: push, pull, fetch, clone, remote (no hay servidor), ni reset, rebase, stash, tag. El simulador avisa cuando se la pides.
  • Los textos de salida están en inglés, como en la mayoría de instalaciones de Git; en tu ordenador pueden salir en castellano según la configuración. Los archivos son planos (sin carpetas reales) y los conflictos se calculan por líneas cuando el número de líneas no cambia; si cambió en ambas ramas, el simulador marca el archivo entero como un solo bloque en conflicto.

Retos guiados

Cada reto te da un repositorio ya preparado y un objetivo. Escribe las órdenes en la terminal y pulsa «Comprobar»: el simulador mira el estado del repositorio, no lo que has escrito. Puedes pedir pistas y reiniciar el reto.

Resolución de conflictos

Un conflicto aparece cuando dos ramas cambian las mismas líneas. Git deja marcas en el archivo: lo que hay entre <<<<<<< HEAD y ======= es tu versión (la rama en la que estás) y lo que hay entre ======= y >>>>>>> es la de la otra rama. Tu trabajo es dejar el texto final y borrar las marcas.
