Un proyecto no se hace solo con buenas ideas: hace falta organizarlo, repartir el trabajo, dejar rastro de lo que se decide y comunicarse bien dentro del equipo. Esta unidad es la **preparación** para el proyecto del módulo: aquí practicas los métodos y las herramientas que usarás después, con ejemplos de la empresa ficticia *Reparaciones Byte Alacant, S. L.*

:::note[Una unidad de formación previa]
La Unidad 0 no figura en la programación didáctica del módulo: es una propuesta del profesorado para llegar al proyecto con las herramientas ya dominadas. Por eso no lleva horas, pesos de evaluación ni criterios propios. Las unidades 1 a 5 son las que cuentan para la evaluación.
:::

## Qué vas a aprender

- Planificar un proyecto: fases, alcance, tareas, tiempos, recursos y riesgos, y representar el plan con un diagrama de Gantt.
- Comparar los ciclos de vida del software y elegir el más adecuado para un caso.
- Entender los valores y principios de las metodologías ágiles y aplicar Kanban, Scrum y estimación ágil.
- Redactar historias de usuario con criterios de aceptación y numerar versiones con el versionado semántico.
- Trabajar con tableros de tareas, control de versiones con Git, correo, mensajería y documentos compartidos.
- Documentar un proyecto: requisitos, informes de avance, documentación técnica, manual de usuario y memoria final.

8. [1.3.4 Versionado semántico](/docencia/smr/proyecto-intermodular/ud00-trabajo-en-proyectos/08-versionado-semantico/): MAYOR.MENOR.PARCHE.
9. [1.3.5 Historias de usuario](/docencia/smr/proyecto-intermodular/ud00-trabajo-en-proyectos/09-historias-de-usuario/): cómo describir lo que necesita el usuario.

## Laboratorios

Cuatro laboratorios interactivos acompañan a la unidad. El primero sirve para planificar y elegir un ciclo de vida; el segundo, para practicar Kanban, Scrum, historias de usuario, estimación, versiones y DevOps; el tercero, para aprender Git y la comunicación de equipo sin riesgo de estropear nada; el cuarto, para preparar los documentos del proyecto.
